# Phase 9.3 — GPS-UX: Live-Tracking + Foto-First-Flow

*Design-Spec, 13. Mai 2026 — Vorbereitung auf v0.9.3*

## Goal

Zwei unabhängige Features die das GPS-Handling der App spürbar verbessern:

1. **Live-Tracking** — User-Position folgt sich selbst auf der Karte, opt-in via Toggle.
2. **Foto-First-Flow** — neuer Spot-Add-Pfad mit Foto + EXIF-Auto-Fill + Map-Tap-Confirm. Behebt das aktuelle Friemel-Problem (User kann Lat/Lng heute nicht selbst setzen — nur "aktueller Standort"-Button, nutzlos wenn man später uploaded).

## Architecture

Beide Features sind isoliert voneinander entwickelbar und shippen zusammen als **Phase 9.3 (v0.9.3)**.

**Files (Übersicht):**
- `components/SpotMap.tsx` — Modify: Live-Tracking-Toggle + Auto-Follow-Logik + FAB-Handler ändert Ziel
- `components/PhotoFirstForm.tsx` — NEW: Client-Component für Foto-First-Page
- `components/PinPickerMap.tsx` — NEW: kleiner leaflet-Wrapper mit single tappable/draggable Pin
- `app/(app)/spots/from-photo/page.tsx` — NEW: Server-Component-Wrapper
- `lib/exif-utils.ts` — NEW: `readExifGps(file): Promise<{lat,lng}|null>`

## Component 1: Live-Tracking

**File:** `components/SpotMap.tsx` (Modify)

### UI

Neuer Toggle-Button auf der Karte rechts unten, **neben** dem existierenden Center-FAB. Vertikal gestackt, Center-Button oben, Tracking-Toggle direkt darunter mit 8px gap.

```tsx
// Pseudocode für Toggle-Button
<button
  onClick={() => setLiveTracking(t => !t)}
  disabled={gpsState !== 'available'}
  aria-pressed={liveTracking}
  aria-label={liveTracking ? 'Live-Tracking deaktivieren' : 'Live-Tracking aktivieren'}
  className="..." // s.u.
>
  <IconLocationFilled size={20} stroke={1.5} aria-hidden />
</button>
```

Style: gleiche Höhe/Form wie Center-FAB (`w-14 h-14 rounded-full shadow-lg`). Active-State `bg-primary text-white`. Inactive-State `bg-white dark:bg-[#1e231a] text-gray-600 dark:text-gray-300`.

### State

```tsx
const [liveTracking, setLiveTracking] = useState(false)  // opt-in pro Session
const [followBroken, setFollowBroken] = useState(false)  // user hat manuell gepannt
```

`liveTracking` wird NICHT in localStorage persistiert — bewusst opt-in pro Session, verhindert "ich hatte das aus Versehen gestern aktiviert und mein Akku ist leer".

### Verhalten

**Wenn `liveTracking=true`:**

- `watchPosition` läuft permanent (NICHT mehr `clearWatch` nach erstem genauen Fix wie bisher Zeile 216-219 in SpotMap)
- Jedes Update mit `accuracy < 200m` (vorher 80m — etwas toleranter für mobile Bewegung) updated `userPosition` state
- Wenn `followBroken === false` → smooth `map.flyTo(latlng, currentZoom, { duration: 0.5 })`
- Updates mit `accuracy > 200m` werden **ignoriert** (vermeidet wilde Sprünge bei schwachem GPS)

**Pan-to-break:**

- Leaflet `dragstart`-Event auf Map → `setFollowBroken(true)`
- Recenter durch Center-FAB → `setFollowBroken(false)` (Center-FAB triggert eh `setCenterTrigger` und das CenterController bewegt die Karte; danach folgt sie wieder)
- Erneuter Tap auf Tracking-Toggle (wenn aktiv ist und Follow gebrochen) → `setFollowBroken(false)` (Re-Engage Follow ohne Toggle aus/an)

**Wenn `liveTracking=false`:**

- Existing Two-Phase-Behavior bleibt: getCurrentPosition (fast) → watchPosition (für ersten genauen Fix, dann clearWatch). Verhalten von vor Welle B.

### Accessibility

- `aria-pressed` reflektiert toggle-state
- `aria-label` ändert sich kontextuell
- Toggle-Button hat `disabled` wenn `gpsState !== 'available'` (analog zu Center-FAB)

### Edge-Cases

- **GPS-Permission verweigert** → Toggle disabled mit `opacity-40 cursor-not-allowed`. Tooltip via `title="Standort nicht freigegeben"` (oder dezenter Toast bei Tap-Versuch — Detail-Decision während Implementation, beides OK).
- **Tab in Hintergrund** → Browser pausiert `watchPosition` standardmäßig; kein Extra-Code. Beim Foreground sollte sich der Watch automatisch fortsetzen.
- **`page route change` (User navigiert von /map weg)** → React-Effect-Cleanup ruft `clearWatch`, kein leak.

**6. Error + Submit:**

- Error: `{error && <p className="text-sm text-red-600">{error}</p>}`

### Flow

```
1. Mount → photo-picker visible, nothing else
2. User picks file
   → setPhoto(file), setPreview(URL.createObjectURL(file))
   → call readExifGps(file) async
3a. EXIF hit:
   → setLat(exif.lat), setLng(exif.lng), setExifSource('exif')
   → show green banner
   → map renders centered on EXIF-coords zoom 16, pin placed there
3b. EXIF miss:
   → fallback: navigator.geolocation.getCurrentPosition (one-shot, low accuracy OK)
     → if success: setLat(gps.lat), setLng(gps.lng), setExifSource('gps')
       → map centered on GPS zoom 14, pin placed (User kann verschieben)
     → if denied/missing: setLat(51.1), setLng(10.4), setExifSource('manual')
       → map centered on DE zoom 6, NO pin yet (waits for tap)
   → show yellow banner
4. User can tap/drag pin on map
   → setLat(newLat), setLng(newLng), setExifSource('manual')
   → banner unchanged (already informational)
5. User fills type/visibility/name (or accepts defaults)
6. Submit:
   → handleAction(): FormData with photo (resized first!), lat, lng, type, visibility, name
   → call createSpot server action
   → on success: router.push('/map')
   → on error: setError(result.error)
```

### Critical Order: EXIF Before Resize

```tsx
const handlePhotoPick = async (file: File) => {
  // STEP 1: Read EXIF on the ORIGINAL file (before resize would strip it)
  const exifGps = await readExifGps(file)
  if (exifGps) {
    setLat(exifGps.lat)
    setLng(exifGps.lng)
    setExifSource('exif')
  } else {
    // fallback to current GPS
    // ...
  }
  // STEP 2: setPhoto for preview (resize happens at submit-time)
  setPhoto(file)
  setPreview(URL.createObjectURL(file))
}

const handleSubmit = async () => {
  if (!photo || lat === null || lng === null) return
  setPending(true)
  // Resize NOW (EXIF was already extracted)
  const resized = await resizeImage(photo)
  const fd = new FormData()
  fd.set('photo', resized)
  fd.set('lat', lat.toString())
  fd.set('lng', lng.toString())
  fd.set('type', type)
  fd.set('visibility', visibility)
  fd.set('name', name)
  const result = await createSpot(undefined, fd)
  if (result?.error) { setError(result.error); setPending(false); return }
  router.push('/map')
}
```

## Component 4: `lib/exif-utils.ts`

```ts
import exifr from 'exifr'

export interface ExifGps {
  lat: number
  lng: number
}

/**
 * Liest GPS-Koordinaten aus EXIF eines Image-Files.
 * Returns null wenn:
 *  - File ist kein Bild
 *  - EXIF fehlt komplett
 *  - GPS-Tags fehlen oder sind ungültig (0/0 wird als invalid behandelt)
 *  - exifr-Library wirft (z.B. korrupte Datei)
 */
export async function readExifGps(file: File): Promise<ExifGps | null> {
  if (!file.type.startsWith('image/')) return null
  try {
    const gps = await exifr.gps(file)
    if (!gps || typeof gps.latitude !== 'number' || typeof gps.longitude !== 'number') {
      return null
    }
    // 0/0 is suspicious — likely missing/zeroed
    if (gps.latitude === 0 && gps.longitude === 0) return null
    return { lat: gps.latitude, lng: gps.longitude }
  } catch {
    return null
  }
}
```

`exifr.gps()` ist der lightweight-Mode der Library und liest nur den GPS-Block (~5kb gzipped). Volle Library wäre ~30kb.

### Change 3: LocationController erweitern

`LocationController`-Component (intern in SpotMap.tsx, Zeile 160+) bekommt neuen Prop `liveTracking: boolean` und einen `onLiveUpdate`-Callback. Wenn `liveTracking=true`, wird der watchPosition NICHT mehr nach erstem genauen Fix clearedt. Bei `accuracy < 200m` (statt vorher 80m) wird `onLiveUpdate(latlng)` gefeuert.

```tsx
function LocationController({ ..., liveTracking, onLiveUpdate }: Props) {
  // existing 2-phase logic
  watchId = navigator.geolocation.watchPosition(
    (pos) => {
      const acc = pos.coords.accuracy
      const latlng = [pos.coords.latitude, pos.coords.longitude]
      if (acc < 80 && !lockedRef.current) {
        // first accurate fix — same as before
        lockedRef.current = true
        onPositionFound(latlng)
        // do NOT clearWatch here if liveTracking is on
        if (!liveTracking && watchId !== undefined) {
          navigator.geolocation.clearWatch(watchId)
          watchId = undefined
        }
      } else if (liveTracking && acc < 200) {
        // ongoing updates while live-tracking is on
        onLiveUpdate(latlng)
      }
    },
    // ...
  )
}
```

In SpotMap-Parent: `onLiveUpdate` setzt `userPosition` UND führt `map.flyTo()` aus, falls `followBroken === false`.

Pan-to-break: Leaflet event `dragstart` auf der Map → `setFollowBroken(true)`. Implementation in einer dedizierten `useMapEvents`-Hook im FollowController.

## Out of Scope

- **Existing AddSpotForm Map-Tap-Erweiterung** — bleibt Quick-Add-Friemel, wird durch Foto-First-Pfad ersetzt für den Standard-Case. Wenn AddSpotForm-Manual eh wenig genutzt wird (post-launch), kann später retired oder eigene Welle bekommen.
- **EXIF-Daten in DB persistieren** — wir lesen nur GPS, der Rest (Aufnahmezeit, Kamera-Modell) wird ignoriert. Kein DB-Schema-Change.
- **EXIF beim Photo-Edit-Flow** (`/spots/[id]/edit-photo`) — der editiert nur das Foto, nicht den Standort. Out of scope.
- **Background-Tracking** (Service-Worker, Geolocation-API beim Closed-App) — keine PWA-Geolocation-Permissions, bleibt browser-Standard.
- **Heading/Compass** (Smartphone-Kompass-Daten für "Marker zeigt Blickrichtung") — Nice-to-have, separate Welle.
